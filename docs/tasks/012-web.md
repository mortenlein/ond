# Task 012 — Ond in the browser (and on the phone)

**Goal:** Ond as a web page: the same engine (WebAssembly), the same screen (WebGL), Web Audio, Web MIDI where the
browser has it. Hosted on Morten's Linux server (static files, HTTPS). No sound change: the same DSP.

## Why it is close

DPF builds the standalone for the web (`dpf__build_jack` under EMSCRIPTEN): the screen through pugl's wasm backend
and WebGL, audio through Web Audio (ScriptProcessor: no SharedArrayBuffer, so no special server headers), MIDI
through Web MIDI (`distrho/src/jackbridge/WebBridge.hpp`).

## Steps

1. **Toolchain:** Emscripten (emsdk) in WSL. Needs Morten's OK (an outside download, ~1 GB).
2. **Build** (`tools/build_web.sh`): the standalone target with `emcmake` → `build/web/Ond.html`, `.js`, `.wasm`.
   The web differences, already in the code (`__EMSCRIPTEN__`):
   - one Ond a page: the plugin's own engine (`OndEngineLoader.hpp`: no library to copy), LINK alone;
   - files: Emscripten's file system (`/ond/...`), kept in the browser (IndexedDB); a way to add WAVs follows;
   - Ond keeps its own time (no Live): BEAT's PLAY;
   - audio starts on a tap (browsers' rule).
3. **Check:** the same sound as the plugin (the baseline through the web build, as through the CLAP).
4. **Host:** the files on Morten's server over HTTPS, with a link to the source (GPL: the repo public, or the source
   offered there).
5. **Phone:** a compact layout (one section at a time, bigger knobs, touch), an on-screen keyboard and pads (iPhone
   Safari has no Web MIDI), installable (`web/sw.js` and the manifest, as Clipper's pages).

## Morten decides
- The repo public on GitHub (or the source offered on the site): needed before the site is public.
- Which server, and how Claude reaches it (SSH, or Morten copies the files).

## Hosting (agreed with ashguard, the host session, 2026-10-31)

- Server **saman**: a small nginx container on the tailnet, public HTTPS through the Cloudflare tunnel (TLS at
  Cloudflare). Proposed hostname **ond.mortenlab.xyz** — Morten decides it, and public or behind Cloudflare Access.
- nginx: `application/wasm`, gzip (Cloudflare adds brotli), long cache for .js/.wasm, no-cache on Ond.html, the
  manifest and the service worker; no COOP/COEP (tell ashguard if the audio moves to AudioWorklet +
  SharedArrayBuffer).
- **Delivery:** a GitHub release per web build on mortenlein/ond, tag `web-<version>`, assets
  `ond-web-<version>.zip` (Ond.html, Ond.js, Ond.wasm; later the manifest and service worker) and
  `ond-web-<version>.zip.sha256`. ashguard's deploy script takes the newest `web-*` release, checks the sum, refuses
  a zip without the three files, unpacks to `~/apps/ond/releases/<version>`, swaps `current` atomically, keeps the
  previous for rollback, verifies HTTPS 200 and the wasm content type. Ping ashguard after the release.
- **Morten (2026-10-31): go ahead on all; behind Cloudflare Access** (not public). The repo was already public.
- Order: Morten approves Emscripten → build, check it sounds as the plugin → Morten: the repo public (GPL: the site
  links to its source) and pushing → release → ashguard deploys → Morten: the hostname.
