# Task 012 — Ond in the browser (and on the phone)

**Goal:** Ond as a web page: the same engine (WebAssembly), the same screen (WebGL), Web Audio, Web MIDI where the
browser has it. Hosted on Morten's Linux server (static files, HTTPS). No sound change: the same DSP.

## Why it is close

DPF builds the standalone for the web (`dpf__build_jack` under EMSCRIPTEN): the screen through pugl's wasm backend
and WebGL, audio through Web Audio (ScriptProcessor: no SharedArrayBuffer, so no special server headers), MIDI
through Web MIDI (`distrho/src/jackbridge/WebBridge.hpp`).

## Steps

1. **Toolchain:** Emscripten (emsdk) in WSL. Needs Morten's OK (an outside download, ~1 GB).
2. **Build** (`tools/build_web.sh`): the standalone target with `emcmake` → `build/web/Ond.html`, `.js`, `.wasm`.
   The web differences, already in the code (`__EMSCRIPTEN__`):
   - one Ond a page: the plugin's own engine (`OndEngineLoader.hpp`: no library to copy), LINK alone;
   - files: Emscripten's file system (`/ond/...`), kept in the browser (IndexedDB); a way to add WAVs follows;
   - Ond keeps its own time (no Live): BEAT's PLAY;
   - audio starts on a tap (browsers' rule).
3. **Check:** the same sound as the plugin (the baseline through the web build, as through the CLAP).
4. **Host:** the files on Morten's server over HTTPS, with a link to the source (GPL: the repo public, or the source
   offered there).
5. **Phone:** a compact layout (one section at a time, bigger knobs, touch), an on-screen keyboard and pads (iPhone
   Safari has no Web MIDI), installable (`web/sw.js` and the manifest, as Clipper's pages).
